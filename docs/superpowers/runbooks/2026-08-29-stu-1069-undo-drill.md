# The undo drill, run against a real apply and a drafting run (STU-1069)

Criteria 16 and 17 of [the pilot gate](../../homelab-pilot.md) ask that `make undo` has
been exercised before `auto_apply` is flipped. Both were run on the serving host against
`seed@example.com` on 2026-08-29, at commit `9f387be`. This is what they took and
what they produced, so the next window does not re-derive it.

`claude:local` by definition: every line needs a consented `Mail.ReadWrite` grant and the
host's own `reports/` and `logs/`.

## No existing run could carry criterion 16

The obvious drill — apply one of the phase-one reports already on disk — does not work,
and the reason is worth knowing before reaching for it. Every report older than
2026-08-29 01:16 names messages that a `make unseed` has since hard-deleted: they resolve
on Graph, but their `parentFolderId` is the **Deletions** dumpster, not Inbox, Archive or
Deleted Items.

That is not a refusal. `label_ids` reports no `INBOX` for such a message, so the executor
reads it as already out of the Inbox and plans an archive with no move — it would stamp
`ec/C` on dumpster mail and journal it as applied. A report outlives its mail, and nothing
on the apply path says so.

So the drill seeds its own round. Two bucket-C fixtures, stacked onto the standing mail:

```bash
# on the host; the seeder refuses without the declaration, which is deliberately not in
# the host's env (docs/homelab-secrets.md: seeding stays a human-run action)
OUTLOOK_SEED_MAILBOX=seed@example.com make seed COUNT=2 MIX=bucket_c=100 ADD=1
```

The push path classified them a minute later as run `f9aa8db0`. Both escalated on
`catch_all` rather than being decided by stage 1 — the structural catch-all rate on this
mailbox — and landed on **one `label_archive` and one `mark_for_delete`**, which is the
richer draw: the drill then covers the folder move and the trash on the same journal.

## 16 — a real apply, then undone

```bash
make apply RUN_ID=f9aa8db0-881d-49d9-8d12-34c849271914
make undo  RUN_ID=f9aa8db0-881d-49d9-8d12-34c849271914
```

The apply is the first on this host to write a `logs/applied/<run-id>.jsonl` at all; every
file there before it was a `.plan.jsonl`. Six operations, no errors:

| | `ewABajVxcAAA` | `ewABajV9LAAA` |
|---|---|---|
| before | Inbox, `[email-classifier-seed]` | Inbox, `[email-classifier-seed]` |
| after apply | **Archive**, `+ ec/C, ec/processed` | **Deleted Items**, `+ ec/deleted, ec/processed` |
| after undo | Inbox, `[email-classifier-seed]` | Inbox, `[email-classifier-seed]` |

The undo journal is the apply's six lines in reverse, all `ok`: `ec/processed` off,
`untrash`, `ec/deleted` off, then `ec/processed` off, `ec/C` off, `INBOX` back on. The
`untrash` lands in the Inbox because Graph's move-out-of-trash always does, which is why
`plan_operations` states the destination rather than inheriting one.

Read the state with `label_ids`, not the folder pane: it is the one axis the executor
diffs on, so a before/after/after-undo triple on it is exactly the claim being tested.

## 17 — a run that drafted

Separate call path and separate evidence: the drafts come from the run's *report*, not its
journal. Run `73e4fa80` is the case the criterion names — a push run under
`auto_apply: false`, so it left a plan and two real drafts and nothing else.

```bash
make undo RUN_ID=73e4fa80-f3c8-4f70-8b3a-0aea012fefe8
```

```
0 operations reverted | 0 errors | 0 messages touched
  drafts: 2 deleted | 0 kept | 0 already gone | 0 errors
```

Zero operations is correct, not a failure — there was no journal to invert, and the run is
undoable for its drafts alone. The whole block is the evidence: `deleted` is proof, `kept`
is a draft a human has since sent or edited and is deliberately left standing, and the exit
code cannot tell the two apart. Two `deleted` lines went into
`logs/drafts/journal.jsonl`, so a later undo will not offer the same drafts again.

One of the two drafts was created by an earlier run, `5798b6f1`, on a conversation
`73e4fa80` also marked `needs_reply`. Taking it is `drafts_of_run` working as written: a
draft this run would otherwise have made, left standing, is the silent survivor STU-854
exists to prevent.

## What the drill left behind

- **The seeded pair stays in the mailbox.** Tearing it down would put `f9aa8db0` in exactly
  the state that made the existing reports unusable above — a report describing mail that
  no longer exists. It is honest phase-one traffic; leave it to the window.
- **`audits/skipped.json` gained a line**, because the drill run produced a report and an
  unaudited report holds back the next `make run` (STU-900). Its verdicts were applied and
  reverted on purpose and stand in no judgement window, so there is nothing to audit.
  The host's checkout is dirty on that file until this branch merges — `make pull-webhook`
  will say so.
- **`make audit-gate` still fails on the host**, on five reports that predate the drill.
  Not this issue's; they need `/validate-classify-run` or their own skip.
